# CanvasTTY Accounts

> **Нужно ядро CanvasTTY с plugin API v2** (сервисы плагинов, участие в запуске, окружения сессий, решающие хуки, инструменты плагинов и действия на карточках, `launch.delegable`): ближайший выпуск после 1.7.0. В CanvasTTY 1.7.0 и раньше этих точек расширения нет, поэтому установка там не пройдёт проверку манифеста.

[English](README.md)

Любой агент на любой модели. Запускайте **Claude Code, Codex, OpenCode, Qwen Code или Kimi** на выбранной модели —
локальной в Ollama, в Ollama Cloud, Z.AI, MiniMax, OpenRouter или любом API, совместимом с Anthropic или OpenAI, —
выбирая её при каждом запуске.

## Как пользоваться

1. Установите плагин и подтвердите его нативный код в **Настройки → Агенты → Extension native code**.
2. Откройте **Учётные записи моделей** (страница настроек плагина) и добавьте запись: провайдер (адрес подставится),
   название, модель, каким агентам её можно использовать. Для API сохраните ключ (только запись). **Проверить**
   показывает модели сервера Ollama на этом компьютере или проверяет формат сохранённого ключа — в платные API ничего
   не отправляется.
3. В окне запуска агента: **Дополнительно → Use CanvasTTY Accounts**, выберите **Model account**, при желании
   **Reasoning effort** и **I trust this folder**.

Оркестраторы получают два инструмента: `canvastty-accounts__list_routes` (все записи × агенты: готова или почему нет)
и `canvastty-accounts__pick_account` (первая готовая запись для агента, неработающие сейчас пропускаются). Оба
возвращают `launchOptions` для `spawn_agent`. Проверяются только записи, нужные запрошенным строкам, по четыре
одновременно; слишком старая для запуска Ollama — `ollama-old` с причиной самого запуска, агент без запрошенного
усилия — `no-effort`, неизвестное усилие — ошибка. Плагин объявляет свои параметры запуска делегируемыми
(`launch.delegable` в манифесте; без этого CanvasTTY не принимает их в `spawn_agent`): выбор оркестратора
меняет только модель, её адрес и усилие рассуждения. *I trust this folder* (доверие через `-c projects=…` Codex или запись в доме
записи) для субагента игнорируется, записываемые
конфигурации (OpenCode, Kimi, `-c` Codex) не содержат ключей одобрений, разрешений и песочницы, а CanvasTTY по-прежнему
применяет к субагенту его профиль, хуки и слой изоляции. Запуск через запись идёт в собственном доме Claude/Codex этой
записи, поэтому настройки `~/.claude` или `~/.codex` человека (его правила allow и deny) там не читаются.

OpenRouter несёт только решения Jev в Ассистенте, но не трафик моделей. Запись на `openrouter.ai` (или его поддомене)
по-прежнему запускает агента, которого вы запускаете сами, но субагенту на ней отказывается, а маршруты помечают её
`decisions-only` без `launchOptions`, поэтому `pick_account` её пропускает. OpenCode на
записи видит только провайдера этой записи (`enabled_providers`), а заголовки, сводки, сжатие контекста и его
собственные субагенты идут на модель записи (`small_model` и `model` каждого встроенного агента), что бы ни было в
вашей глобальной конфигурации OpenCode.

Квота. Для записей Z.AI и BigModel (GLM Coding Plan) сервис сам читает квоту плана по своему расписанию, открыта ли
какая-нибудь страница или нет: `GET /api/monitor/usage/quota/limit` на собственном адресе записи (`api.z.ai` или
`open.bigmodel.cn`), с ключом этой записи, без перенаправлений. Чаще — пока запись используется, раз в несколько минут —
пока квота исчерпана, сразу после ожидаемого сброса, и редко — в простое (не больше 40 чтений в час; при ошибках
интервал растёт). `list_routes` показывает у такой записи `quota` (состояние, сколько процентов осталось, окно, время
сброса, источник, время и давность чтения, достоверность), а `pick_account` пропускает запись с исчерпанной квотой.
Чтение старше 30 минут — `stale`: неизвестно, но никогда не «исчерпано». Если время сброса прошло, квота «вероятно,
сброшена» и читается снова; если чтение показывает запас раньше ожидаемого сброса, исчерпание снимается сразу
(досрочный или бонусный сброс). Состояние переживает перезапуск (`quota.json` в папке данных плагина, без ключей).
Квоты других провайдеров не читаются.

### Учётная запись для других расширений (запросы через CanvasTTY)

Отметьте у учётной записи API (не Ollama и никогда не OpenRouter) *Другие расширения могут отправлять запросы к модели
через эту учётную запись*, чтобы другое расширение, например маршрутизатор Auto (Jev) из Assistant, могло отправлять
через неё отдельные запросы к модели. Ключ подставляет сам CanvasTTY и отправляет запрос только на адрес учётной записи:
другое расширение ключа не видит. По умолчанию ничего не предлагается, и одной галочки мало: каждое расширение вы ещё
разрешаете в **Настройки → Агенты → Нативный код расширений → CanvasTTY Accounts**. Этот плагин пропускает каждый запрос
по квоте учётной записи (исчерпанный план GLM отклоняется до сброса) и учитывает его после. Проверьте, что условия тарифа
это допускают. Нужен CanvasTTY с такими запросами (сервисы `brokerable`).

### Учётные записи подписок (пулы)

Несколько ваших собственных входов на агента (Claude Code, Codex, Grok, Kimi) — например, несколько учётных записей
Claude или тридцать Grok. **Добавить** в разделе *Учётные записи подписок* создаёт для записи свою папку внутри папки
данных плагина и открывает карточку со входом самого агента (браузер, пароль или Google): вы входите один раз на каждую
запись, а CanvasTTY не видит ни пароля, ни токена. При добавлении вы указываете, насколько доверяете записи данные
(D0–D3 или *Не задано* — решить позже); за вас ничего не выбирается.

Запуск с *Model account → пул <агента>* (или `launchOptions` оркестратора `{"canvastty-accounts":{"account":"pool:grok"}}`)
получает запись с наибольшим остатком квоты: сначала с точно прочитанной квотой, затем с оценённой, затем с неизвестной,
почти исчерпанные — последними; исчерпанные (до сброса или досрочного сброса), без входа и уже занятые карточкой
пропускаются. Одна карточка на запись одновременно, потому что токен обновления каждого входа одноразовый;
восстановленная карточка продолжает на своей записи. Квоты читает CanvasTTY (`limits.get {provider, home}`, нужно
`limits:read`) — не больше 32 папок на плагин; у остальных квота «неизвестна». `list_routes` показывает записи пула как
`kind: "subscription"` с квотой и доверием, `pick_account` выбирает сначала из пула.

Записи пула работают только на этом компьютере (worktree — можно): вход никогда не копируется на другую машину. Для
Qwen Code пула нет (его домашнюю папку нельзя перенести, бесплатный OAuth закрыт), для OpenCode Go тоже (это API-ключ:
добавьте его как учётную запись модели). Удаление стирает папку записи вместе со входом; Claude Code на macOS хранит вход
в Связке ключей — чтобы убрать и его, сначала наберите `/logout` в карточке на этой записи.

### Тарифы для кодинга (GLM, MiniMax)

GLM Coding Plan (Z.AI `api.z.ai` или BigModel `open.bigmodel.cn`) и MiniMax Coding Plan (`api.minimax.io` или
`api.minimax.cn`) входят по API-ключу, а не через браузер. **Добавить подписку** у тарифа в *Учётных записях подписок*
спрашивает название, регион, ключ, уровень доверия данных (за вас ничего не выбирается), сколько карточек может работать
на записи одновременно (по умолчанию 2) и можно ли её использовать Auto и другим расширениям. Ключ хранится в секретах
плагина и привязан к хосту тарифа: больше никуда он не отправляется. Несколько записей одного тарифа образуют его пул.

*Model account → пул GLM Coding Plan* (`pool:glm` или `pool:minimax`) запускает Claude Code или OpenCode на записи с
наибольшим остатком квоты, пропуская записи без ключа, исчерпанные (до сброса) и достигшие своего предела карточек. Оба
агента идут на Anthropic-совместимый адрес тарифа (`/api/anthropic` у Z.AI и BigModel, `/anthropic` у MiniMax); Claude
Code получает модель тарифа для основных слотов и малую для Haiku, OpenCode — только провайдер тарифа (со списком
моделей тарифа), все его встроенные агенты закреплены на нём.

Модели берутся из собственного списка каждой записи: `GET …/models` тарифа на хосте записи с её ключом (MiniMax
`/v1/models`; у GLM такой адрес не задокументирован, поэтому спрашивается `/api/coding/paas/v4/models`, а без ответа
используется встроенный список), раз в сутки и по «Прочитать сейчас»; иначе — встроенный список плагина (GLM-5.3 и
GLM-5.3-Flash; MiniMax-M3 и MiniMax-M3.1-Flash, проверено 2026-10-25). Пока вы не выбрали модель в записи, она работает
на самой новой из списка (наибольшая версия не Flash; для малого слота — самая новая Flash; у MiniMax — самая новая
Flash во всех слотах) и переходит на более новую,
когда та появляется. Записи со старой моделью (glm-4.6, MiniMax-M2, …) один раз переводятся на самую новую, и страница
об этом сообщает. *Model* в окне запуска запускает другую модель из списка тарифа на один запуск; маршруты, выбор,
общие чтения и предложения брокера перечисляют модели каждой записи тарифа. Квота GLM читается из
`/api/monitor/usage/quota/limit`, MiniMax — из `/v1/token_plan/remains` (окна 5 ч и неделя; у ключа с оплатой по факту
`sk-api-` квоты тарифа нет, она остаётся неизвестной). Записи, сохранённые раньше с пресетом Z.AI или MiniMax, появляются
здесь со своими ключами. `list_routes`, `pick_account` и общие чтения показывают их как `kind: "subscription"` с `plan`.

## Что меняется при запуске

- Claude Code: `ANTHROPIC_BASE_URL` (для Ollama — корень сервера), `ANTHROPIC_AUTH_TOKEN` (ключ или `ollama` для
  локального сервера), все уровни моделей = модель записи, `--model`, и адрес повторён в `--settings`, чтобы настройки
  проекта не могли перенаправить ключ. Claude работает в собственном `CLAUDE_CONFIG_DIR` записи в папке данных
  плагина, первичная настройка пропущена. Его `.claude.json` сохраняет то, что записал Claude; файл, который не является объектом
  настроек, откладывается как `.claude.json.unreadable`, нечитаемый отменяет запуск, а папки домов закрыты (0700).
- Codex: провайдер только через `-c` (Responses API), каталог из одной модели в личной папке запуска, собственный
  `CODEX_HOME` записи, переменная ключа через `env_key`.
- OpenCode: личный файл `OPENCODE_CONFIG` (API Anthropic получают `/v1`), ключ как `{env:…}`.
- Qwen Code: `--auth-type openai` и `OPENAI_*`. Kimi: провайдер `openai_legacy` в `--config` (без ключа) или личный
  `--config-file`.
- Ollama на этом компьютере: модель закреплена как `имя:local`, поэтому сервер сам не отправит её в облако; перед
  запуском проверяется, что Ollama работает, модель установлена и умеет вызывать инструменты.
- Каждый запуск через запись отмечается `thirdPartyModel` (кроме собственного API поставщика агента: Anthropic для
  Claude Code, OpenAI для Codex), и CanvasTTY запускает профиль **Авто** как «только правки» в песочнице CLI: авто-
  проверкой CLI была бы модель записи, а классификатор слабой модели — не граница безопасности.
- Субагент в папке, выбранной человеком для его оркестратора (или внутри неё): папка, которую CanvasTTY передаёт как
  `trustedFolder`, отмечается доверенной в собственной конфигурации Claude записи (Codex получает её от CanvasTTY).

Ключи хранятся в зашифрованных секретах плагина; в окружение агента их кладёт сам CanvasTTY и маскирует во всём, что
читают другие агенты. В `~/.claude`, `~/.codex`, `~/.qwen`, `~/.kimi` и `~/.ollama` ничего не пишется, собственные
входы агентов для адреса записи не используются.

Если при старте службы сохранённые записи не прочитались, страница, лаунчер, запуски и инструменты отказывают, пока
очередное чтение не удастся; поверх них ничего не сохраняется. Сохранение и привязка ключа меняют то, что показывает
служба, только после того, как CanvasTTY их записал. Ответ Ollama читается до 4 МиБ. Между службой и CanvasTTY кадр не
больше 1 МиБ, вызов хоста завершается ошибкой через 30 с или сверх 64 одновременных, ждущие события и журнал
ограничены 8 МиБ.

Нужен CanvasTTY с точками запуска для учётных записей (списки `optionsFrom`, `launchOptions` в `spawn_agent`, слияние
`--settings` для Claude).

## Разработка

`ESBUILD=/путь/к/esbuild node scripts/build.mjs` собирает `services/accounts.mjs` и `settings/accounts.js` и
обновляет манифест. `npm test` запускает тесты (с `CANVASTTY_REPO` — ещё и валидатор манифеста CanvasTTY).
